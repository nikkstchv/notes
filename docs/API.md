# API модуля заметок

Все эндпоинты требуют авторизованного пользователя. `userId` берётся из контекста авторизации (JWT / session), **не из тела запроса**.

Формат ошибки:

```json
{
  "statusCode": 404,
  "message": "Note not found",
  "code": "NOTE_NOT_FOUND"
}
```

Общие ошибки для всех эндпоинтов:

| Статус | Когда |
| --- | --- |
| `401` | Нет или невалиден токен |
| `500` | Непредвиденная ошибка сервера |

Чужая заметка всегда выглядит как отсутствующая: **`404`**, не `403`. Так нельзя перебором UUID узнать, что заметка существует у другого пользователя.

---

## POST `/notes`

Создать заметку текущего пользователя.

**Вход**

```json
{
  "title": "Список покупок",
  "content": "Молоко, хлеб"
}
```

- `title` – обязательная непустая строка
- `content` – необязательная строка

**Ответ `201`**

```json
{
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "title": "Список покупок",
  "content": "Молоко, хлеб",
  "userId": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
  "createdAt": "2026-08-13T20:00:00.000Z",
  "updatedAt": "2026-08-13T20:00:00.000Z"
}
```

**Ошибки**

- `400` – пустой `title`, неверный тип полей

---

## GET `/notes`

Список **своих** заметок. Чужие не попадают в выборку: фильтр всегда `userId = currentUser`.

**Query**

| Параметр | Описание |
| --- | --- |
| `limit` | Размер страницы, по умолчанию `20`, максимум `100` |
| `cursor` | Непрозрачный курсор предыдущей страницы (`createdAt` + `id`) |

Сортировка: `createdAt DESC`, `id DESC`.

**Ответ `200`**

```json
{
  "items": [
    {
      "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
      "title": "Список покупок",
      "content": "Молоко, хлеб",
      "userId": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
      "createdAt": "2026-08-13T20:00:00.000Z",
      "updatedAt": "2026-08-13T20:00:00.000Z"
    }
  ],
  "nextCursor": "eyJjcmVhdGVkQXQiOiIyMDI2LTA4LTEzVDIwOjAwOjAwLjAwMFoiLCJpZCI6IjNmYTg1ZjY0LTU3MTctNDU2Mi1iM2ZjLTJjOTYzZjY2YWZhNiJ9"
}
```

`nextCursor: null`, если следующей страницы нет.

**Ошибки**

- `400` – `limit` вне диапазона или битый `cursor`

Пагинация заложена в контракт сразу, чтобы не ломать клиент, когда у пользователя станет много заметок.

---

## GET `/notes/:id`

Получить одну свою заметку.

**Вход:** `id` в пути (UUID).

**Ответ `200`** – объект заметки, как в `POST`.

**Ошибки**

- `400` – `id` не UUID
- `404` – нет такой заметки **или** она чужая

---

## PATCH `/notes/:id`

Изменить свою заметку. Реализованный метод: `NotesService.updateNote`.

**Вход**

Путь: `id`. Тело – хотя бы одно поле:

```json
{
  "title": "Продукты на неделю",
  "content": "Молоко, хлеб, яйца"
}
```

Разрешено менять только `title` и `content`. `content: null` очищает текст. Нельзя передать `id`, `userId`, `createdAt`, `updatedAt` – сервис их игнорирует и в `data` Prisma не кладёт.

**Ответ `200`** – обновлённая заметка (`updatedAt` выставляет БД).

**Ошибки**

- `400` – `id` не UUID, пустое тело, пустой `title`, неверные типы
- `404` – заметки нет или она чужая

---

## DELETE `/notes/:id`

Удалить свою заметку.

**Вход:** `id` в пути.

**Ответ:** `204` без тела.

**Ошибки**

- `400` – `id` не UUID
- `404` – заметки нет или она чужая
